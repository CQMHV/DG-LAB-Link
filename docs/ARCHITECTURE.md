# 架构说明

DG-LAB Link 采用“React 观察与配置，Rust 持有实时链路”的结构。窗口刷新或前端热更新不会成为设备输出链路的时钟源。

```text
React UI
    │ Tauri commands / snapshot events
    ▼
Hub actor
    ├── 编译期 SourceFactory 注册表
    ├── 多设备、逐通道输入源路由与逐设备强度状态
    └── DG-LAB Socket V4 客户端
            │ WSS
            ▼
      官方 Relay ── DG-LAB 4 App ── 设备
```

## 运行边界

- Rust 后端负责官方 Relay 连接、多个 APP 与设备状态、波形节拍、逐设备逐通道路由、队列和紧急停止。
- React 前端只调用经过校验的命令，并展示低频状态快照；原始实时波形不会逐采样穿过 IPC。
- 所有实时通道使用有界队列，过期数据不追赶补发。
- Socket V4 是当前主协议。旧协议只在出现真实兼容需求后独立增加。

## 输入源

输入源通过 `SourceFactory` 编译期注册表扩展。每个输入源负责校验自己的配置并生成统一的波形帧；协议编码只发生在 V4 边界。输入源页面可以指定本次运行中新接入设备 A/B 共用的默认来源，也可以选择“每次询问”使新设备两路保持未分配；已有设备的逐通道绑定不会被覆盖。

注册表随二进制一起构建，首版不扫描目录、不加载动态库，也不提供运行时插件安装。每台设备的 A、B 通道分别绑定一个输入源实例；同一设备和目标通道同一时刻只使用一个来源。每台设备还可独立开启 A/B 输入源同步：开启时两路立即重置为当前默认源（默认源为“每次询问”时两路均变为未分配），后续修改任一路都会同时更新两路；关闭时保留当前绑定并恢复独立选择。

## 通道输出

Hub 每个节拍先按输入源实例对设备通道绑定分组，每个实际使用的输入源只拉取一帧，再把该帧发送给绑定的设备与 A/B 通道。因此，多路共享实时 OSC 等状态型来源时不会重复消费；A、B 绑定不同来源时则在同一节拍分别取帧。开始输出前，每台在线设备的 A、B 都必须完成分配；运行中接入的设备若有默认来源会自动加入，没有完成两路分配则留在待配置状态。为保持队列有界，单次输出集合最多 32 台，启动时超过上限会明确报错。控制台按设备呈现仪表盘标签；主窗口切换标签只更新当前调节焦点，每个标签也可创建绑定该 `controlId` 的独立 Tauri Webview 窗口。所有窗口订阅同一个 Hub 快照，设备强度与输入源命令都显式携带目标 `controlId` 和通道，因此独立窗口不依赖主窗口当前选中项。关闭设备窗口仅销毁该 Webview，只有主窗口关闭或进程退出才进入全局安全清理。A、B 强度和手机端反向控制锁按设备独立维护。“同步所有设备”默认关闭；开启时，Hub 以发起操作的仪表盘设备为基准对齐全部设备的 A/B 强度。后续调整先校验所有在线设备各自的通道上限和在途操作，再根据每台设备当前值计算不同的相对增量，使其达到同一目标强度。

运行中切换某台设备的一路输入源时，Hub 只清空该设备实际发生变化的目标通道并移除该路旧波形的在途记录；若该设备已开启 A/B 源同步，则两路一起清理并切换。其他设备始终继续输出。普通停止逐台清空输出集合；紧急停止清空并归零所有在线设备。一台设备断开时其余设备继续，所有输出设备均断开后才停止输出。

## 设置生命周期

安全上限和最长输出时间保存在当前 Hub 运行状态中，保存后立即生效。首版不写入本地配置；退出并重新启动应用后恢复编译时默认值，真机验收时每次启动都必须重新确认低强度限制。

## 配对流程

后端连接 `wss://trex.dungeon-lab.cn/v4`，从 `hello` 帧取得控制方 ID。界面据此生成 DG-LAB 4 App 可扫描的配对链接。APP 接入后，后端维护 APP、设备槽位和设备状态的快照与增量更新。

## 开发用被控端模拟器

`simulator/` 是独立的浏览器应用，通过真实 Socket V4 Relay 以被控方身份接入，不参与生产 DG-LAB Link 的运行路径。它在一个 APP 会话中维护最多 8 台虚拟 `COYOTE_030` 设备，并实现控制端当前需要的协议子集：

- `devices.get`、`devices.snapshot`、`devices.patch` 与 `slots.patch`；
- `AppendPulseData`、`AddIntensity`、`SetTempIntensity`、`SetMute` 和仅归零的 `SetIntensity`；
- 全 APP、单设备和单通道的 `device.op.clear`；
- `ping`、`custom.action` 与完整 RPC 成功/错误响应。

模拟器将每台设备和 A/B 通道的状态分别保存，可用于观察寻址是否串台、单设备断开是否影响其余设备，以及手机端反向强度变化是否按设备同步。它不模拟蓝牙时序、电气负载或真实体感。

## 安全原则

- 非零强度只通过 V4 支持的相对调整或临时强度操作完成；绝对强度操作只用于归零。
- 停止输出和应用退出会对整个输出集合进入清理路径；运行中切换某台设备的输入源只清空该设备的目标通道，另一通道和其他设备继续输出。APP 断开只移除其设备，其余设备继续。
- 紧急停止优先于普通波形命令。
- 真机测试必须从低上限和低强度开始，且始终保留可立即断开的物理手段。

## 构建与发布

`build:client` 只生成 React 客户端，并作为 Tauri 的 `beforeBuildCommand`；`build:sites` 在此基础上另外准备 Sites Worker 和托管清单。当前 `bundle.active = false`，所以 Tauri 生产构建只输出裸可执行文件；安装包、更新包和签名 bundle 不在首版产物范围内。
