# DG-LAB 真机验收清单

协议自动测试不能覆盖手机网络、APP 调度、蓝牙连接和实际设备行为。每次发布前应使用 DG-LAB 4 App 完成以下低强度验收。

## 准备

- [ ] 记录 Windows、DG-LAB Link、DG-LAB 4 App 和设备固件版本。
- [ ] 手机已联网，APP 已通过蓝牙连接设备。
- [ ] 在 APP 中将 A/B 通道上限设置为低值，并确认紧急断开方式可用。
- [ ] 每次启动 DG-LAB Link 后，确认 APP 上报的低通道上限与当前基础强度，并在设置页检查已保存的连接超时配置。
- [ ] 测试人员保持清醒且全程观察，不进行无人值守测试。

## 连接与设备同步

- [ ] 启动 DG-LAB Link，确认尚未连接 Relay、没有输出或音频活动；点击“连接 Relay 服务”后状态进入“等待 APP”。
- [ ] 使用 APP 扫描配对二维码，确认界面显示 APP 已连接。
- [ ] 确认设备名称、槽位、A/B 当前强度和通道上限与 APP 一致。
- [ ] 同时接入至少两台设备，确认设备页完整列出，并可分别切换当前控制设备。
- [ ] 确认控制台为每台设备显示一个仪表盘标签；切换标签后，A/B 强度、电量和通道状态均属于对应设备。
- [ ] 将两台设备的仪表盘分别拉出独立窗口，确认各窗口只调整自身设备；关闭其中一个设备窗口不停止输出，也不关闭主窗口或另一设备窗口。
- [ ] 断开并重新连接 APP，确认旧会话被清理且新二维码/会话可正常使用。

## 低强度输出

- [ ] 在第一台设备标签为 A、B 选择不同输入源，并为第二台设备选择另一组合；确认顶部显示“混合”，且各路波形只到达对应设备和通道。
- [ ] 在第一台设备开启“A/B 同步”，确认两路立即重置为当前默认源；修改 A 或 B 任一路后，另一选择器同步变化，第二台设备不受影响。
- [ ] 关闭第一台设备的“A/B 同步”，确认当前两路值保留，随后 A、B 可再次独立切换。
- [ ] 从零或极低强度开始，启动 5 秒输出。
- [ ] 确认波形连续、没有明显追赶突发，停止后不再产生新帧。
- [ ] 确认同一测试波形同时发往 A、B，再分别以低幅度调整 A、B 设备强度，确认两个强度值不被联动修改。
- [ ] 两台设备同时输出时切换当前控制设备，确认旧设备持续输出，且新设备的 A/B 强度可独立调整。
- [ ] 调整强度时确认界面、APP 与设备状态一致，且不会超过 APP 上报的上限。

## 清理与故障路径

- [ ] A/B 绑定触控模式后，验证自由坐标、快捷格、律动网格、轴交换和映射曲线；切换波形格会切换波形，停留同一格保持游标连续。
- [ ] 验证 A、B、同步、分离多点和交替触控路由，第二台设备或另一个窗口的触点不会串到当前设备。
- [ ] 静止按住一秒以上，确认续租保持输出；松手、Pointer Cancel、窗口失焦、切页和关闭窗口后，目标通道停止触控波形且基础强度不变；可选背景波形按预期恢复。
- [ ] 验证渐变强度在静止按住时仍随时间变化；触控释放时另一设备和非触控通道持续输出。
- [ ] 桌面端分别选择 MP3、FLAC、WAV、M4A、AAC、OGG 文件，验证播放、暂停、停止、跳转与波形；异常/过大文件错误可见，旧输出不残留。
- [ ] 导入 MP4、M4V、MOV、MKV、WebM 视频，确认自动使用音轨并支持播放、暂停、跳转和循环；多音轨优先默认可解码音轨，无音轨或全部编码不受支持时显示错误并保持静默。验证视频 2 GB 上限与音轨一小时上限。
- [ ] 验证麦克风的权限拒绝、设备不可用和正常采集；静音/输入中断时波形归于静默。
- [ ] 开启“桌面音频”，在默认播放设备播放浏览器、音乐或游戏声音，确认左右声道音量与波形响应；静音超过一秒仍保持监听，声音恢复后继续。停止监听、切换麦克风/文件、紧急停止和退出后旧特征不残留；更改默认播放设备或断开设备后显示停止与重新开启提示。
- [ ] 用左右声道内容不同的音频验证 A/B 的声道、增益、音量阈值、迟滞、观察频段和周期曲线均独立；关闭任一路音频输出不影响另一路。
- [ ] 录音后回放并保存 WAV，确认声音和波形时间轴一致；录音过程中紧急停止会关闭采集，所有设备清空并归零。

- [ ] 输出过程中点击普通停止，确认设备任务被清空。
- [ ] 输出过程中点击紧急停止，确认两个通道立即归零并清空任务。
- [ ] 输出过程中只切换其中一台设备的 A 通道输入源，确认只清空该设备 A 的旧任务，B 通道与其他设备保持输出。
- [ ] 输出过程中断开承载全部剩余设备的手机网络或关闭最后一个 APP，确认桌面端进入断开状态并停止输出。
- [ ] 多设备输出中断开其中一台或其所属 APP，确认其他设备继续输出；全部设备断开后才停止。
- [ ] 没有其他持有者时退出桌面应用，确认设备没有残留输出任务。

## GUI、CLI 与 MCP 共享会话

- [ ] 按 [CLI/MCP 使用说明](CLI_MCP.md) 启动后台 CLI，记录本次 holderId；确认 GUI、CLI `status` 与 MCP `dglab://status` 的 controllerId、设备 controlId 相同。
- [ ] 在 GUI 选择第一台设备，通过 CLI 或 MCP 显式修改第二台设备的低强度与输入源；确认只影响目标设备，GUI 能看到同一变化。
- [ ] 通过 CLI/MCP 以第二台设备为基准开启全设备同步，确认强度取自明确的基准设备，不取 GUI 当前焦点。
- [ ] GUI 启动低强度输出，分别通过 CLI 和 MCP 普通停止、紧急停止，确认普通停止的设备范围以及紧急停止的全设备清空、归零与音频停止行为相同。
- [ ] 保留后台持有者并退出 GUI，确认现有共享会话仍运行；重新打开 GUI，确认读取同一会话。
- [ ] 释放指定后台 holderId，确认其他 GUI/CLI 不受影响；释放最后一个持有者后，十秒内确认设备清空、归零、音频停止、Relay 断开。
- [ ] 重启核心，确认没有自动恢复 Relay、输出、触点或音频采集；完成测试后释放本次创建的全部持有者。

## 结果记录

- [ ] 记录测试日期、测试人、设备型号和全部异常。
- [ ] 若协议行为与自动测试不一致，先保留捕获日志并停止发布，不以提高强度重复试验。
