# 架构重整与回归验收

初次验证日期：2026-10-03；未发布应用基线修正：2026-10-04。评审基线 `0dc1cbc`；开始时工作区干净。修改按本地提交分批保存，没有推送、PR、远程服务写入或真机输出。

## 已实施的边界

- 保留 core、CLI、GUI、MCP 四个程序及独立原生插件。新增 `dg-lab-link-contracts` 作为命令、领域数据、快照、错误和效果分类的唯一来源；客户端生产依赖树不含 core 实现、btleplug、cpal 或 symphonia。
- 前端命令和快照从 Rust Schema 生成；一致性检查纳入 `npm run check` 和客户端构建。删除旧 V4 专用连接命令、共享设备焦点、触控／音频专用 host 命令、旧快照投影和重复的核心插件 DTO。
- 普通停止先撤销目标输出和排队波形，再在 actor 外等待清理。并发停止、慢回执和清理失败均不恢复输出；普通停止保留基础强度及插件采集／音频活动。
- 绑定拥有源、设备、通道、配置、修订号、活动状态和代次，采用不透明 UUID。换源销毁旧绑定并清空配置。实例与绑定配置均要求 `expectedRevision`，冲突不会启动或配置插件。
- 包级生命周期门闩覆盖更新／卸载和实例集合及使用；失败恢复目录／注册表并允许重试。包锁缓存使用可回收的 Weak 引用；打包输出必须在输入目录之外，采用临时文件原子发布。
- 偏好文件仅在不存在时初始化默认值。解析和领域校验失败阻止启动，保留原文件；写入同样校验。配置使用当前单一格式，不提供历史应用配置迁移。
- SDK 私有 IPC 包含操作代次，异步操作保留原上下文。长期服务通过 `begin_operation()` 为新外部事件显式创建新上下文，不刷新旧任务、不自动重试停止前的业务。
- 插件 UI 采用有界读取、跨面板合并和按绑定／修订号区分的缓存。容器和表单 disabled 向子控件传播；配置草稿冲突提供重新加载入口。公共动作和配置接收任意 JSON，插件自行校验具体格式。
- 核心程序显式关闭 Tokio runtime，异步十秒清理期限结束后不因阻塞文件工作线程无限等待退出。正常清理及 Windows Job Object 继续负责插件子进程回收。

## 问题与回归证据

| 评审问题 | 正式回归位置与覆盖 |
| --- | --- |
| 两台设备并发停止、失败清理后仍活动 | Hub 模拟 Relay：同时停止、慢回执、清理失败、另一设备继续操作、基础强度保留 |
| 更新期间新建／启动旧实例、卸载后重启 | plugin-runtime 真实原生 fixture：包生命周期与实例创建、启动、配置、删除交错；回滚和重试 |
| 旧 V4 刷新影响其他协议 | CLI 删除旧入口；Hub 指定 connectionId 刷新及多协议会话隔离 |
| 换源串用通道配置 | Hub：新 UUID、空配置、修订号归零、旧绑定无效 |
| 偏好失败后覆盖原数据 | ControlService／PreferencesState：坏类型、非法波形、BLE 参数、端点、未知字段和失败写入，原文件不变 |
| 同实例双通道／多窗口 UI 失败 | 原生 UI 并发、有界等待、停止后不重启；React 共享缓存和不同绑定独立文档 |
| 陈旧草稿覆盖隐藏字段 | 实例／绑定 CAS、并发配置和回滚；React 冲突提示与显式重新加载 |
| disabled 未传播 | React：布局、表单、字段及提交按钮继承禁用状态 |
| CLI 拒绝合法标量动作 | CLI：数字、字符串、布尔、数组、null 与对象；标量配置携带修订号 |
| 打包输出截断输入文件 | package：输入目录、大小写／路径别名、已有输出失败保留、成功原子发布 |
| 停止 A 忽略 B 的在途错误 | Hub：按目标绑定／代次过滤 V4 波形结果，其他设备有效错误仍处理 |
| 旧异步插件业务跨停止复活 | 真实原生 SDK／IPC：旧延迟调用失效、新上下文成功、旧副本继续失效 |
| 包锁缓存无限增长 | 1024 个不存在插件 ID 请求及活跃读写互斥／缓存回收 |
| 阻塞文件 I/O 拖住进程退出 | core-server：已进入阻塞 worker，runtime 退出无需等待 worker 完成；独立程序持有者清理回归 |
| 绑定事务回滚重新拉起已停止或故障的实例 | 真实 native fixture：校验与 Hub 提交阶段停止被拒绝；应用／提交失败恢复旧值且 PID／启动次数不变；原会话崩溃后回滚失败且不自动重启 |

第二批补齐跨入口取消和会话身份：ControlService、插件回调及 WebSocket 转发同一 core 接受代次，客户端以单调最大值接收更新。真实 WebSocket 验证直接 core 停止会广播新代次并拒绝旧请求；真实原生插件验证停止后旧 UI／启动请求不能重新创建进程，新显式启动仍可成功。配置后台子任务在开始时再次检查原代次。

插件运行时在实例锁内再次检查原接受代次，覆盖路由到实例之间的调度窗口；原生回归确认陈旧的启动、动作、UI 和实例配置不创建新进程，不改变配置及修订号。绑定配置事务共用原会话，回滚失败不会再次启动实例。

V4 事件携带连接代次；V4、V3、BLE 的显式连接创建独立会话。模拟 Relay 和替换后端覆盖旧事件、迟到断开、慢清理回执、十秒超时、刷新中停止、重复连接、已断开连接的幂等处理，以及退出时对清理中的旧 V4 会话归零。等待不占 Hub actor，其他协议设备继续操作；结束的会话任务及时回收。

## 当前开发接口

应用尚未发布，当前接口是初始开发基线，内部重构不构成应用版本升级。宿主、客户端、SDK 和预装插件使用同一套接口及初始插件协议 `protocolVersion: 1`；不保留历史应用版本兼容、端口配置迁移或 profile 重建流程。插件包更新中的 `migrate` 是插件管理能力，配置 `revision` 是并发修订号。

客户端使用 `connections` 与每设备／绑定数据；窗口自己保存焦点。连接管理使用 `connect_transport`、`disconnect_connection`、`refresh_connection_pairing`。触控、音频及第三方使用 `set_source_config`、`source_action`、`source_input`。普通写入超时或停止取消后不自动重试，先读取当前状态。
