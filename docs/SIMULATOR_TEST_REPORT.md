# 输入模式模拟机验证记录

验证日期：2026-09-30，Windows。功能基线为 `0bb1106`；同时验证本次提交中的模拟机修复。

## 环境与方法

- 编译并启动当前 Tauri 调试客户端，确认通过官方 Socket V4 Relay 配对后能够识别两台虚拟郊狼。
- 使用项目自带的 `simulator/` 被控端模拟器，Relay 为 `wss://trex.dungeon-lab.cn/v4`。模拟器使用真实 WebSocket，不使用主界面的浏览器演示 bridge。
- 连续场景由临时 Rust 驱动直接编译项目的 `hub.rs`、`dglab/`、`sources/` 和 `model.rs`，调用与 Tauri 命令相同的 Hub API。驱动与读数保存在 Git 忽略的 `tmp/`，其 Cargo example 注册在验证后移除。
- 从模拟器实际显示的每设备 A/B 波形包计数、帧内容和强度核对结果。音频采用仓库内合成的 `video-aac.mp4`，左右声道分别为 440 Hz 和 880 Hz；桌面回环使用独立播放器向默认播放设备发送同一测试音。

## 实测结果

| 场景 | 结果 |
| --- | --- |
| 默认 Relay 配对 | 只输入控制端 ID 即可接入，Rust Hub 识别两台设备及各自 A/B 通道。 |
| 固定波形基准 | 两台设备的 A/B 独立收包，四通道基础强度均为 10。 |
| 自由触控 | 第一台 A 通道收到 `0A0A0A0A64646464`，其余通道继续运行；松开后收到零幅度帧，基础强度仍为 10。 |
| 律动触控 | 选定区域后持续收包，能够在运行中切换模式与输入源，Hub 无输出错误。 |
| 视频音轨、左右分离 | MP4 音轨解析成功，分析峰值约为 445/891 Hz；A/B 实际帧分别为 `0D0D130D2B2A0F1C` 与 `57575054292A0E1D`，确认声道映射独立。 |
| 循环、暂停、继续、跳转 | 循环播放持续收包；暂停后 A/B 归为零幅度帧，第二台继续输出；继续与跳转后重新产生音频特征。 |
| 桌面音频 | WASAPI 回环处于 `desktop/capturing`，左右峰值约为 445/891 Hz；模拟器实际帧为 `0D0D0D0D2A2A2B29` 与 `575757572A292929`。停止后采集状态为 idle，音量与峰值归零。 |
| 单设备停止 | 第一台 A/B 波形包均停在 3234；复核时仍为 3234，第二台从约 3358 增长到约 4320，确认停止互不影响。 |
| 紧急停止 | Hub 输出状态为 stopped、活动设备数为 0，模拟器四通道基础强度全部归零，包计数停止增长。另在 Relay 保持接入时短时复核，结果相同。 |

模拟器的“最后一帧”是接收历史预览，停止后仍保留；不能将该预览视为仍在输出，应同时核对包计数、清理操作和强度。

## 本次发现并修复

- 模拟器默认地址带有多余的末尾 `/`，官方 Relay 在该路径握手失败。改为与 Rust 控制端一致的 `/v4`，新增默认路径回归测试，并通过默认配置实际接入。
- 客户端与模拟器的 Vite 开发服务共用依赖优化缓存，同时启动时出现两份 React，导致模拟器空白并报 Invalid hook call。为模拟器隔离缓存目录，并预优化 React 与 renderer；两个开发服务并行运行时页面恢复正常。

修复后的模拟器测试 **10/10 通过**，`npm run build:simulator` 通过；当前桌面客户端调试编译通过。输入模式实现此前已通过 Rust **128 项测试**、独立 Windows 回环启停测试 **1 项**、前端 **51 项测试**、Clippy 与客户端构建。

## 验证边界

官方 Relay 在较长测试期间发生过远端重置和重新配对；以上连续输出场景在已接入会话中完成，紧急停止另外在连接有效时复核。未进行长时间网络稳定性验收。

本次没有连接 DG-LAB 真机；未逐项操作全部原生界面控件，也未通过模拟器验收麦克风录音、录音保存和每一种视频格式。相关解码、映射及状态逻辑已有单元测试覆盖，真实蓝牙输出与设备能力仍按 `REAL_DEVICE_CHECKLIST.md` 验收。
