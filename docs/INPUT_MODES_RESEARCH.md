## 触控模式

官方触控模式包含两种面板，配置和状态按设备插槽维护。

| 子模式 | 操作与输出 |
| --- | --- |
| 自由触控 | 上部自由区域将触点两轴分别映射为波形频率和波形相对强度；下部是 4×2、共八个快捷波形区域，按住某一区域时持续播放该区域对应的波形。上下区域可连续滑动切换。 |
| 律动触控 | 整个面板划分为波形区域，可选 2×2、3×3、4×4，默认 4×4。触点进入哪个区域就持续播放哪个区域的波形，手指可以保持不动，也可以滑入其他区域切换。 |

两类波形区域均可编辑替换、恢复默认或随机换批。静态控制器在触点跨入另一格时切换波形，停留同格不会反复重启播放器；没有证据表明“律动触控”会分析点击节拍。

### 自由区域的映射

教程明确说明：默认横轴控制波形相对强度，纵轴控制波形频率，可以交换两轴。界面把频率设置显示为**周期（ms）**，周期越小，频率越高。郊狼当前设置界面允许周期 `10..100 ms`、波形相对强度 `0..100`。

频率映射由可编辑节点定义，节点之间逐渐插值。强度映射有两种方案：

- **经典模式**：触点位置决定相对强度，节点之间插值；位置不变时强度保持不变。
- **渐变模式**：触点在指定区域时，相对强度会随时间自动变化。左侧渐变从高到低，右侧渐变从低到高；两侧渐变让中间区域维持最高强度，两侧产生渐变。因此，实现仅依赖坐标的静态映射不足以覆盖官方行为。

经典映射可添加、移动、编辑或删除节点，端点位置固定，最多六个节点。渐变强度映射的节点主要定义区域边界，不提供相同的自由增删与数值编辑。

默认经典映射的四节点坐标为 `0、0.33、0.66、1`，相对强度为 `0、100、100、0`，周期为 `100、10、10、100 ms`。静态实现采用分段线性插值并取整。渐变则另外维护每通道的当前值、方向与增量，触点区域位置决定速度档；精确时间行为仍应通过运行对照验证。

### 通道与松手

官方提供以下通道分配方式：

| 方式 | 触点分配 |
| --- | --- |
| A 或 B 单通道 | 一个触点只控制选定通道。 |
| AB 同步 | 一个触点同时控制 A、B，产生相同波形。 |
| AB 双指 | 先按下的触点控制 A，后按下的触点控制 B。 |
| AB 轮替 | 每次新的按下在 A、B 之间轮替，从 A 开始。 |

静态控制逻辑表明，松手会结束该触点的触控播放意图，并在调度节拍中释放触控输出；没有把基础通道强度归零。官方允许触控与自由组合同时启用：按下时覆盖背景组合波形，松手后由下层组合继续输出。因此，官方的松手行为需要结合是否存在背景任务理解。

郊狼触控中间件主线只提交波形数据，没有调用修改基础通道强度的接口。触控强度轴控制的是波形内部的相对值。

## 音频模式

官方音频模式包含三个入口，共用声音到波形的映射能力。

| 入口 | 行为 |
| --- | --- |
| 本地 | 导入音频文件，播放时分析并生成波形；提供进度、循环与扬声器输出控制。 |
| 实时 | 使用系统麦克风持续收音，分析后生成波形。静态入口调用 `startMicrophone`；本次没有发现系统播放声音回环采集入口。 |
| 录音 | 先通过麦克风录制并保存，再回放录音文件生成波形。记录路径不订阅通道输出，回放路径才启动文件模式输出。 |

Android 当前导入白名单为 MP3、FLAC、WAV、M4A、AAC、OGG；文件上限 200 MB，时长上限一小时。录音至少五秒，最长一小时，保存为 MP3。这些是当前 APP 的产品限制，不自动成为桌面端的必要限制。

### 声音如何映射为波形

音频分析同时控制两个维度：

1. **声音强度 → 波形相对强度**。低于蓝色下限时为零，达到红色上限时达到最高相对强度。提供固定范围与自适应两种方式。
2. **声音频谱 → 波形频率**。选取观察频段，在图谱中突出该频段内频谱分量最高的位置，再通过可编辑的分段映射决定输出波形周期。观察的是音频的 Hz，输出设置显示为 ms，不能直接混用。

自适应方式还包括：

- 数据增益：放大参与映射的音频数据。
- 有效范围：约束红、蓝映射线可移动的范围。
- 高适应系数：声音持续达不到上限时，逐步降低红线。
- 低适应系数：声音持续高于下限时，逐步提高蓝线。
- 迟滞：条件连续满足一段时间后才开始调整。

从设置对象和界面核实到的默认值如下，作为行为对照基线，而非要求硬编码的项目配置：

| 参数 | 4.2.6 默认值 | 当前界面范围 |
| --- | --- | --- |
| 强度映射 | 自适应 | 自适应 / 固定范围 |
| 数据增益 | 2.5 | 1..10 |
| 强度有效范围 | 0.05..1 | 0..1 |
| 高 / 低适应系数 | 各 0.1 | 各 0..0.5 |
| 迟滞 | 0.3 秒 | 0..2 秒；内部按 100 ms 单位保存 |
| 观察频段 | 100..1000 Hz | 50..10000 Hz |
| 周期映射 | 四节点，归一化位置 0、0.33、0.66、1 分别对应 10、100、10、100 ms | 周期 10..100 ms，中间节点位置可调整 |

官方实现共享麦克风或文件播放生产者与时间轴，并为各设备通道保存映射配置、执行状态和独立输出开关；提供左右音频声道选择及 A/B 设置同步。教程把顶部左右声道控件描述为共享功能，但读取到的控件处理实际写入当前通道的 `audioChannel` 设置，这一作用范围应在 APP 中再核对。

音频中间件提交的是波形数据，基础通道强度仍由通道控制器管理。共享播放结束、通道关闭与基础强度归零是不同的操作。

### 尚不能确认的算法细节

声音转换核心位于 WASM，JS 将每段音频和各通道配置传给 `batch_section_pulse`，取回四个频率采样、四个相对强度采样，以及图谱和自适应执行状态。播放与录音代码按 100 ms 块推进，与项目现有帧形态相符。

本次没有逐指令分析 WASM，也没有输入音频与输出帧的对照实验，所以以下内容仍未确认：强度统计采用峰值、RMS 或其他度量；频谱窗口和窗函数；静音/噪声处理；插值、取整及自适应变化的精确公式。现有证据支持声音强度和频谱映射，不能声称已核实完整 DSP 算法或 BPM 节拍检测。

## DG-LAB Link 的实现边界

目前实际注册的内置来源只有 `builtin.fixed_waveform`。`SourceFactory` 可以复用，但 Hub 初始化、输入源页面文案和配置组件仍围绕固定波形组织，新增 Factory 本身不足以完成新模式。

| 现有边界 | 对新输入源的影响 |
| --- | --- |
| `WaveSource::next_frame()` 同步返回 `WaveFrame` | 两模式都可使用当前波形输出模型；采集或文件解码不能阻塞拉帧。 |
| Rust 每 100 ms 调度，帧内四个 25 ms 采样 | Rust 负责生成、调度和发送，前端只提交触控事件与配置，展示低频反馈。 |
| 普通来源按实例取一次帧后扇出 | 音频采集可共享；各绑定的映射参数与自适应状态应独立。触控须按设备与通道保存状态，防止共享实例串台。 |
| 所有窗口共享 Hub | 触控事件应显式携带目标设备、通道与窗口/控制会话身份，避免两个窗口争用同一路。 |
| 同一目标通道只能有一个活动输入源 | 官方触控覆盖背景组合不能直接实现为同时绑定两个来源。若纳入对应能力，应在触控来源内部定义背景波形与覆盖规则。 |
| 当前 Source 无输入事件、采集生命周期或运行诊断接口 | 需要补充动态状态入口、开始/停止、错误与活动状态；通过有界缓冲传递数据。 |

“周期 ms”“声音频率 Hz”“设备频率编码”和“通道绝对强度”必须继续区分。当前 Rust `WaveSample` 存储的是设备频率编码和 `0..100` 的波形脉宽相对值；新增映射要显式做单位转换。

建议后续按以下顺序实现：

1. 增加两类内置 Factory、动态状态入口与生命周期管理；输入源页管理模式配置，控制台展示当前触控板或音频运行控件。
2. 触控先完成自由 / 律动面板、经典 / 渐变映射和既有 A/B 路由。移动事件合并为最新状态，Rust 保留时间、生成四采样帧。
3. 音频在独立 Rust worker 中进行麦克风采集、文件播放/解码和分析；共享采集，再按各设备通道映射。录音复用同一采集路径，回放复用文件路径。
4. 输入失效时撤销相应通道的输出：触控松手、取消、失焦、窗口关闭、状态超时，以及音频暂停、结束、采集设备断开。清理应只作用于相关设备通道，并检查现有全局队列代次机制，避免干扰其他输出。
5. 用模拟器验证路由、波形范围与清理，再用官方 APP 和低强度真实设备对照行为。音频算法在选定峰值/RMS、频谱与自适应方案后，应明确区分功能对应与数值完全一致。

桌面端系统音频回环可以作为扩展候选，但它不属于本次核实的官方实时麦克风入口；是否加入、平台支持和采集依赖应另行评估。当前未选择或新增音频依赖。
